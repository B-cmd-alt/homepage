AI agents · evaluation · 2025–2026

Memory System Evaluator

Ten agent-memory systems, one model, one embedder, one calibrated judge — and every number traceable to the case that produced it.

The question. Every memory vendor reports a benchmark score, and the scores do not survive contact with an independent run: self-reported numbers in the nineties, independent re-runs in the thirties to forties. Audits of the most-quoted benchmark found 6.4% of its answer key wrong and a judge that accepts most intentionally wrong answers. Before comparing memory systems, I had to build an evaluation I could trust.

What I built. An OpenAI-compatible shim so that Mem0, Zep/Graphiti, A-MEM and Microsoft GraphRAG run on exactly the same generator and embedding model as the baselines; adapters for ten systems spanning 2023 → 2026 (BM25, vector RAG, hybrid + reranker, GraphRAG, Mem0, Graphiti, A-MEM, and faithful re-implementations of Generative Agents, Mastra Observational Memory and the Anthropic memory tool); a self-built benchmark, SixAxis, that takes the core of LongMemEval, MemoryAgentBench, BEAM, ConvoMem, Memora, MemOps, ForgetEval and MemDelta and fixes each one's documented flaw — gold answers carry evidence pointers, every question ships two decoys the judge must reject, updates are scored as current / stale / other, deletion and poisoning are first-class; and a strict judge protocol calibrated at κ = 0.87 against independent labels after my earlier study found standard LLM-as-judge inflating results by 6–22 points.

What it shows so far. On recall, a 2023 keyword index and a 2025 agentic memory layer are indistinguishable. Where the systems differ is cost, updates, deletion and robustness — which is why the benchmark has six axes instead of one score. GraphRAG tops the table at 0.98, but partly on its own answer prompt and 11,000 tokens per query; the model-managed-files pattern is the most expensive read path and the weakest modern system; and the Generative Agents memory stream, run faithfully, is simply not built for factual questions. None of the scores were tuned to make a system look good, including mine.

Data infrastructure · autonomous agents · 2026

PipelineAgent

A detection-and-repair agent for data pipelines that watches the data, not the job.

The question. The pipeline failure that hurt me most in production was never a crash. It was a job that exited 0 every morning while writing nothing, for weeks, under monitoring that only watched exit codes. I wanted an agent that notices from the data itself, says "I don't know" when it cannot look, and repairs what it can without ever being allowed to grade its own work.

What I built. A fleet of seven real, free, genuinely flaky public feeds (NWS, Open-Meteo, USGS, FRED, GitHub Status, CoinGecko, Ontario's grid operator) running hourly on Cloud Run into an append-only, vintage-stamped warehouse. Three out-of-band detectors — write recency, head lag, flat value — each returning exactly OK, BREACH or UNKNOWN, where UNKNOWN is rendered amber and never green. A findings ledger with explicit dispositions, a dead-man's switch whose heartbeat carries the hash of the running code (so "committed" and "deployed" cannot silently diverge), and a policy test that refuses any pull request that loosens an SLA to make a finding disappear. The repair agent triages deterministically, reproduces the failure by replaying the archived bytes, asks a model for a minimal patch, and hands the patch to a separate gate: on PASS it merges, deploys and verifies; if the detectors stay red it reverts; after three attempts it escalates with exactly one issue.

What it shows so far. Real sources break in ways synthetic ones don't: a government data feed that answers once and then resets connections, a market API that rate-limits, a grid operator whose hour-ending column is fixed EST all year so the obvious daylight-saving conversion is wrong. The dashboard is a static page the loop itself renders, with its own staleness check — so a dead loop cannot leave a green page behind.
